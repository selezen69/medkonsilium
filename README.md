# МедКонсилиум

Закрытое семейное приложение. Основной сценарий: **вопрос → документы при необходимости → обсуждение ИИ-специалистов → общий итог**.

## Состояние разработки

Первая работающая основа, версия 0.1. Это часть реализации [ТЗ 1.1](medconsilium-spec-v1.md), не завершённая первая версия по всем критериям ТЗ.

Работает:

- Вход по email и паролю, закрытая регистрация по одноразовому приглашению на конкретный email.
- Администратор и участники семьи; серверная проверка прав на профили, разговоры, файлы и исправления.
- Журнал просмотров администратором, блокировка участников с отзывом всех сеансов.
- Вопрос без документов, дополнительные сообщения, сохранение истории на сервере.
- Загрузка PDF, PNG, JPEG до 8 МБ; проверка типа по содержимому; обнаружение дублей в профиле; закрытое скачивание оригинала.
- Ручной ввод и подтверждение текста документа, история его исправлений. Оригинал не меняется.
- Настраиваемый серверный адаптер OpenAI: координатор, отдельные первичные мнения, взаимное рассмотрение, итог. Пользователь сам выбирает 1–4 роли; автоматический подбор пока не реализован.
- Версии обсуждений, состояния выполнения, неполный результат и повтор после ошибок.
- Печать завершённого результата с профилем и источниками через браузер — в том числе «Сохранить как PDF».
- Адаптивный интерфейс для компьютера и телефона.

Пока не реализовано:

- Автоматическое OCR и проверка извлечённых показателей. В текущей версии текст документа вводится вручную; файл без проверенного текста блокирует запуск консилиума.
- Голосовой ввод, отдельная медицинская сводка, назначения и напоминания.
- Автоматический выбор специалистов, прямое адресование вопроса отдельной роли.
- Отдельный проверенный механизм раннего оповещения о медицинской срочности. Инструкция ИИ сама по себе таким механизмом не считается.
- Восстановление пароля пользователем, управление резервными копиями через интерфейс.
- Интеграции с часами и мобильные приложения.

Без API-ключа и явно выбранной модели приложение сохраняет вопросы и документы, но **не генерирует медицинские ответы**. В интерфейсе это обозначено. ИИ-роли не являются реальными врачами, а их согласие не является независимой проверкой.

## Техническая основа

Node.js 24+, встроенные HTTP, crypto и SQLite. Фронтенд — HTML/CSS/JavaScript без сборки и внешних зависимостей. SQLite выбран как начальный вариант для небольшой семьи на одном сервере; это проектное решение реализации, а не ранее согласованная инфраструктура.

Для размещения нужен постоянно работающий Node-процесс и сохраняемый диск. Этот вариант **не предназначен для Vercel Functions или статического GitHub Pages**. Публичное размещение в этом изменении не выполнено. При переходе на несколько экземпляров сервера необходимо вынести БД, задания и ограничители запросов в общие сервисы.

## Первый запуск

1. Установить Node.js 24 или новее и открыть папку репозитория.
2. Скопировать `.env.example` в `.env`.
3. Выполнить `npm run setup`: указать имя, email и пароль администратора (6–200 символов). Пароль вводится скрыто. По умолчанию первый аккаунт создаётся локально. Альтернатива для запуска через браузер описана ниже.
4. Выполнить `npm start` и открыть `http://localhost:3000`.
5. Войти и открыть «Семья», чтобы создать приглашение. Ссылка показывается администратору для личной передачи; приложение её не отправляет.

Если порт изменён, изменить также `APP_ORIGIN`. `npm install` для работы не требуется.

### Первый аккаунт через браузер

Для запуска без терминальной формы оператор может задать `BOOTSTRAP_TOKEN`: случайную секретную строку не короче 32 символов. После запуска открыть в браузере адрес приложения с фрагментом `#setup=СТРОКА`. Строку нельзя коммитить, публиковать или отправлять посторонним: до создания первого аккаунта она разрешает создание администратора.

Пользователь сам вводит имя, email и новый пароль в форме. Ссылка сразу удаляется из адресной строки и после создания первого аккаунта перестаёт работать. Запрос защищён проверкой Origin, ограничением попыток и повторной проверкой состояния БД в транзакции. Без настроенного токена этот маршрут закрыт. После первого запуска удалить BOOTSTRAP_TOKEN из окружения.

## Подключение ИИ

В `.env` указать **обе** переменные: `OPENAI_API_KEY` и `OPENAI_MODEL`. Модель должна поддерживать Responses API и выбранные параметры. Модель и стоимость не выбираются автоматически. Перезапустить сервер.

Адаптер использует [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create) и передаёт `store: false`. Это не обещание отсутствия любых журналов или сроков хранения у поставщика; условия обработки медицинских данных следует проверить перед реальным использованием.

Выбранные документы передаются только как проверенный текст с ID и именем; оригиналы поставщику не загружаются. ИИ получает контекст только текущего разговора выбранного профиля. Общей медицинской памяти между разными разговорами пока нет.

На обсуждение с N специалистами выполняется 2N + 2 запросов: координатор, N первичных мнений, N повторных мнений, синтез. Одновременно допускается два обсуждения; лимит пользователя — 10 запусков в час. Пределы считаются в памяти процесса и сбрасываются при его перезапуске.

## Хранение и развёртывание

Все пользовательские данные, включая оригиналы файлов, находятся в `DATA_DIR/medkonsilium.sqlite` и SQLite WAL-файлах. `data/` и `.env` исключены из Git. Не добавлять реальные документы, пароли, токены или БД в репозиторий.

До семейного использования:

- Выбрать место хранения и условия передачи данных поставщику ИИ.
- Настроить HTTPS перед Node и точный внешний `APP_ORIGIN`; установить `COOKIE_SECURE=true`. Для внешнего адреса сервер проверяет эти условия при запуске. Прокси не должен кэшировать ответы или журналы запросов с медицинскими данными.
- Настроить доступ ОС к каталогу данных и шифрование диска. В этой реализации нет прикладного шифрования SQLite.
- Настроить резервирование и восстановление. Самый простой начальный порядок: остановить сервер, скопировать весь каталог DATA_DIR в защищённое место, затем запустить. Для восстановления остановить сервер и заменить каталог копией. Проверить это сначала на вымышленных данных. Автоматическое резервирование ещё не реализовано.
- Определить сроки хранения и процедуру удаления данных. Пользовательского удаления пока нет.
- Проверить медицинские ограничения и сценарии срочности до использования ответов для реальных решений.

## Проверка

`npm run check` — синтаксические проверки. `npm test` — интеграционные проверки входа, приглашений, разграничения данных, CSRF, документов, блокировки, перезапуска и отказов ИИ. Поставщик ИИ в тестах заменён управляемым ответом; реальный платный API и медицинская корректность ими не проверяются.
